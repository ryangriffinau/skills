# Public-changelog mode

Use for broad product news or release notes intended for many readers.

## Keep

- Lead with a broadly applicable action only when readers must migrate, upgrade
  or change configuration. Never include customer-specific billing or access.
- Frame entries around the product capability and who benefits.
- State availability, compatibility, migration requirements and known limits.
- Keep technical terms that help users find, configure or evaluate the feature.
- Link to public documentation, migration steps or the release when available.

## Cut

Remove private customer facts, internal tracker IDs, team process, confidential
metrics and roadmap promises that are not approved for publication.

## Shape

1. Required action, when broadly applicable
2. Release summary
3. Changes grouped by user-facing capability
4. Availability, compatibility and known limits
5. Public links

_Mode check:_ a reader with no project access can understand whether the change
affects them and what, if anything, to do.
